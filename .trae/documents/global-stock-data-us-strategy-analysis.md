## 2. 一句话结论

这不是选股策略仓库，而是一份面向 AI 编程助手的“美股/港股公开数据 API 代码手册”。

它能提供行情、K 线、财务、期权、FINRA 空头成交、SEC 申报和宏观数据的示例调用，但没有：

- 可交易美股标的池
- 多因子定义与合成
- 横截面统一评分
- 买卖规则与仓位管理
- point-in-time 数据库
- 回测、成本模型和样本外验证
- 调度、持久化、监控和生产级容错

因此，它适合作为“数据源适配器原型”，不适合作为现成的美股选股系统，更不能仅凭仓库中的技术指标、`vol/OI` 或 short-volume 排行直接生成交易信号。

## 3. 仓库的真实产品形态

仓库没有业务源码目录。所有功能均以内嵌代码片段存在于 `SKILL.md`，使用者需要把整份 Markdown 注入 AI 上下文，再由 AI 选择并执行片段。

其实际结构是：

`自然语言请求 -> AI 选择 SKILL.md 中的函数 -> 直接请求第三方 HTTP API -> 返回 dict/list`

这带来两个特点：

1. 部署简单，只依赖 `requests`。
2. 缺少稳定的软件边界。函数没有统一模型、版本化接口、自动测试、数据血缘和可观测性。

README 所说的“13 层”是能力分类，不是运行时管线。这些层之间没有自动编排，也没有统一数据存储。

## 5. 仓库里真正存在的“筛选逻辑”

### 5.1 行情排行

`market_stock_list()` 只支持按以下单字段服务端排序：

- 涨跌幅
- 成交量
- 成交额
- 最新价
- 振幅
- 当日高低价

它是行情榜单，不是策略筛选器。没有市值、流动性、证券类型、上市时间、财务质量或风险过滤的组合。

### 5.2 SEC 单因子横截面

`market_frame()` 获取某个 XBRL 标签在某期的全市场值；`frame_screen()` 只做数值上下限；`frame_ranking()` 只做单字段排序。

例如可以找“研发费用最高的公司”，但不能直接得到：

- 研发费用率
- 研发增长率
- ROE/毛利率/自由现金流复合质量分
- 行业内排名
- 市值中性化排名
- 可交易股票代码

返回行只有 CIK、公司名、值和期末日，甚至没有 ticker。

### 5.3 技术指标

仓库计算 MA、MACD、RSI、KDJ 和布林带，但没有把指标转换成标准化因子，也没有定义组合评分、Top N、调仓频率或持有期。

其中 RSI 使用窗口内简单平均涨跌，而不是 Wilder 平滑；EMA 从首个收盘价直接启动，缺少 warm-up；空 K 线会令 MA/MACD 路径触发 `IndexError`。

## 6. 值得肯定的实现

### 6.1 数据源边界写得清楚

仓库明确区分 SEC/Treasury/CFTC、FINRA、CBOE/Yahoo/东财等来源的使用条款，没有把“公开可访问”错误等同于“可商用”。

### 6.2 官方源统一限流

`official_get()` 使用线程锁实现进程内限速，并区分：

- 资源确实不存在
- SEC User-Agent 配置错误
- 限流、封禁或网络故障

这比简单的 `except Exception: continue` 更可靠。

### 6.3 时间与格式问题有真实修复历史

变更历史显示作者修复过：

- Yahoo/东财请求漏传参数
- 腾讯美股、港股字段下标错误
- 美东冬令时下 0DTE 日期错误
- SEC Frames 时点科目要求 `I` 后缀
- OCC 调整后合约根包含数字

这说明作者对端点做过实测，而不是只整理文档。

### 6.4 SEC Frames 有低成本横截面价值

一次请求获取一个 XBRL 指标的全市场截面，是仓库中最值得借鉴的能力。适合构建财务候选集或做数据完整性核验。

## 7. 关键问题与选股风险

### 7.1 严重：没有 point-in-time 选股能力

SEC Frames 返回的数据被裁剪为 `cik/entity/value/end`，丢弃了申报日期、表单、accession 等字段。历史选股无法判断某个财务值在当时是否已经公开。

`sec_xbrl_facts()` 虽保留 `filed`，但仅按来源顺序取最后 20 条，没有：

- 按 `filed <= signal_time` 过滤
- 去除同一期间的重复或修订事实
- 区分单季值、年初至今值和全年值
- 处理公司自定义标签与口径变化

直接回测会产生前视偏差和财务期间错配。

### 7.2 严重：K 线并未真正使用复权价格

文档称 Yahoo “适合需要复权数据的场景”，但函数只读取 `indicators.quote.close`，没有读取 `adjclose`，也没有单独处理拆股和分红。

这会污染：

- 跨拆股收益率
- 动量和均线
- 波动率
- 回测持仓收益

分钟时间戳还使用本机时区 `datetime.fromtimestamp()`，没有转换到交易所时区。

### 7.3 严重：期权“异动”和方向解释过度

代码将 `volume/open_interest > 1` 直接解释为“新建仓”。这是不成立的：

- 当日成交量包含开仓和平仓
- 一笔成交同时有买方和卖方
- 当日 OI 通常不能告诉你成交方向
- 需要次日 OI 变化才能辅助判断新增持仓

`net_delta_exposure_shares = delta * volume * 100` 也不是可交易意义上的净 Delta 敞口。代码不知道成交发生在 bid 还是 ask，也不知道客户与做市商方向；把 call 的正 Delta 和 put 的负 Delta直接相加，会产生看似精确但方向不可识别的数字。

这些指标最多标记“高活跃合约”，不能单独解释为看多、看空或做市商对冲压力。

### 7.4 严重：标的池混入不可直接交易类别

东财 Nasdaq 榜单在线抽查直接出现了权证代码 `CYCUW`。函数没有证券类型字段或过滤器，也没有排除：

- ETF、杠杆/反向 ETF
- 权证、units、rights
- 优先股
- SPAC
- OTC
- 低价股和低流动性股票
- 上市时间不足的股票

同时 NASDAQ、NYSE、其他市场是分开的，没有统一去重、ticker 主数据或历史成分。它不能直接作为生产美股 universe。

### 7.5 高：SEC 接口实现存在两套不一致出口

Layer 9-12 使用带限流与真实联系人检查的 `official_get()`，但 Layer 7 的：

- `sec_filings()`
- `sec_xbrl_facts()`
- `ticker_to_cik()`

仍直接使用硬编码 `SEC_HEADERS = "... contact@example.com"` 和 `requests.get()`。

这绕过了统一限流，也违背“必须配置真实 SEC 联系方式”的要求。在批量选股时可能触发 SEC 拒绝访问。

### 7.6 高：横截面数据无法直接合并

不同来源分别使用：

- ticker
- CIK
- 东财 `secid`
- 东财 `SECUCODE`
- Yahoo symbol

仓库只提供低效的 ticker -> CIK 线性扫描，没有统一 security master、反向 CIK -> ticker、证券类型、交易所、币种和公司行动映射。多因子 join 很容易错配双重上市、ticker 变更和多股权类别。

### 7.7 高：财务横截面口径不可直接比较

SEC Frames 的覆盖率因标签差异明显。仓库也承认营收至少有两个常见标签，但只建议取并集，没有定义：

- 标签优先级
- 同一公司重复事实去重
- 财年不同公司的季度对齐
- 单位与缩放校验
- IFRS/foreign private issuer 处理
- 异常值和重述处理

因此“全市场排名”是原始事实排名，不是可直接进入模型的标准化因子。

### 7.8 高：缺少生产级可靠性

除 Yahoo session 外，大部分请求没有：

- 重试与指数退避
- 本地缓存和数据版本
- schema 校验
- 数据源熔断
- stale 标记
- 跨源一致性检查
- 请求日志和指标

来源接口是未承诺稳定的网页端点，字段变化曾导致两个腾讯函数长期 100% 崩溃，历史也有五个函数因漏传参数始终返回空数据。

### 7.9 中：FINRA short volume 容易误读

仓库正确提醒 short volume 不等于 short interest，但仍需进一步约束：

- 分母是 FINRA 文件所覆盖场所的 reported total volume，不等于全市场 consolidated volume
- 做市和流动性提供会让比例天然偏高
- 绝对比例不能直接作为做空拥挤或未来下跌信号

更合理的因子是个股自身的滚动标准分、变化率和相对行业分位，并与 short interest、借券费率、成交量状态联合解释。

### 7.10 中：技术指标适合展示，不适合直接研究复现

- RSI 不是常见交易终端的 Wilder RSI
- EMA/MACD 没有稳定 warm-up 约定
- 布林带使用总体标准差，未声明口径
- 没有缺失值、重复日期、异常价量校验
- 没有与 TA-Lib、交易终端或黄金样本对照测试

不同实现产生的信号日期可能不同。

### 7.11 中：合规结论仍需法务复核

仓库把 Treasury/CFTC 归为 S 级时明确写了“未逐条核验条款正文”。“美国政府作品不受版权保护”也不等同于所有数据、商标、第三方嵌入内容和接口使用均无额外限制。

CBOE、Yahoo、东财、新浪、腾讯、Nasdaq 被仓库自身列为 C 级，不能作为商业产品的默认生产数据源。

- Yahoo chart 使用浏览器 User-Agent 时返回 200；无该头的抽查曾返回 429，说明访问策略依赖环境。
- SEC `Assets/CY2025Q4I` 返回 6,159 条事实，验证 instant period 修复有效。
- FINRA `CNMSshvol20260723.txt` 文件可读取，字段与解析顺序一致。
- Nasdaq 财报日历返回 200。

这些结果只能证明代表性端点当前可达，不能替代自动回归测试，也不能证明全部 30+ 端点稳定。

## 9. 对美股选股最有价值的借鉴

### 第一优先：SEC 事件与财务事实增量层

保留以下思想：

- 每日 8-K、Form 4、13F、10-Q、10-K 事件流
- XBRL companyfacts 作为公司财务事实来源
- SEC Frames 作为横截面批量获取和覆盖率核验

必须补齐：

- 以 `filed/accepted` 为生效时间
- accession 级版本管理
- 同期事实去重和重述处理
- 标签到标准财务科目的映射
- CIK、ticker、交易所、股权类别统一主数据

### 第二优先：宏观和事件门禁

- 收益率曲线用于利率 regime
- 财报日历用于财报窗口禁入或降仓
- 8-K/Form 4 用于事件标签

它们适合作为选股后的风险门禁，不应直接混成不透明总分。

### 第三优先：FINRA 短空成交异常

只使用时间序列异常，不使用绝对值判断：

`zscore(short_volume_ratio, 60d) + 5d change + liquidity controls`

将其作为情绪/拥挤辅助因子，权重应低于价格趋势、质量和盈利修正。

### 第四优先：期权活跃度

可以保留：

- 0DTE/近月合约筛选
- P/C volume 与 P/C OI
- 成交量加权 IV
- vol/OI 作为“活跃度”标签

必须删除“vol/OI > 1 就是新开仓”的解释；方向信号需要成交侧、成交价相对 bid/ask、次日 OI 变化和事件日过滤。

### 第五优先：多源字段实测方法

腾讯字段下标、SEC period 和 OCC 格式的修复过程值得借鉴：对没有正式 schema 的源建立固定响应样本、字段契约测试和每日 canary，而不是依赖注释。

## 10. 不应直接借鉴的部分

- 将网页私有接口作为商业生产主数据源
- 直接遍历当前榜单构造历史股票池
- 未复权 K 线计算动量和回测
- 用单期 XBRL 原始值直接跨行业排名
- 把 `vol/OI > 1` 当作新增仓位
- 把 `delta * volume` 当作净方向敞口
- 把 FINRA short-volume 高比例直接解释为看空
- 用单一技术指标阈值替代因子验证
- 让 AI 临时拼接代码承担生产数据管线

## 11. 与 tick-stock-panel 的对照

| 维度 | global-stock-data | tick-stock-panel |
|---|---|---|
| 本质 | 数据接口代码手册 | A 股规则选股与研究平台 |
| 主要市场 | 美股、港股 | A 股 |
| 标的池 | 当前行情列表，未净化 | 全 A 股池 + 基础过滤 |
| 策略 | 无完整策略 | 25 个规则策略 |
| 因子 | 原始指标和单字段排名 | 77 因子、IC/IR、去重、组合 |
| 评分 | 无统一评分 | 候选内 min-max 加权 |
| 回测 | 无 | 有撮合、成本、持仓、退出 |
| 样本外验证 | 无 | 嵌套 walk-forward + purge/embargo |
| 数据工程 | 多来源调用原型 | 有管线和持久化，但存在历史成分偏差 |
| 最佳借鉴点 | 美股数据适配与官方事件源 | 策略执行、因子研究和验证框架 |

二者是互补关系：

`global-stock-data 的美股数据适配思想 + tick-stock-panel 的研究/回测框架`

但不能简单拼接。中间必须增加统一主数据、point-in-time 存储、复权和可交易标的池。

## 12. 针对现有美股系统的推荐落地

现有系统已有 Futu 实时行情与交易链路，不建议用此仓库的新浪、腾讯、东财或 Yahoo 快照替换已验证主链路。合理定位是“研究增强层”：

1. Futu/Longbridge 继续承担稳定行情、证券主数据和交易相关能力。
2. SEC EDGAR 提供财报事实与申报事件。
3. Treasury/CFTC 提供宏观 regime 原料。
4. FINRA 和期权数据仅作为低权重辅助证据。
5. 每个 Asset 继续独立请求和独立生成信号，避免跨标的异常互相污染。
6. 全部结果进入统一报告/策略中心，不在数据采集模块内直接给出交易结论。

推荐管线：

`数据源适配 -> 统一证券主数据 -> 原始数据版本库 -> PIT 标准化 -> 可交易池 -> 因子计算 -> 横截面评分 -> 风险门禁 -> 回测/OOS -> 报告中心`

## 13. 可落地的美股选股因子

从该仓库能衍生、但必须重构后才能使用的因子：

1. 质量：ROE、毛利率、经营现金流/净利润、净负债率。
2. 成长：营收和 EPS 的同比增长、增长加速度。
3. 研发：研发费用率与行业内研发强度，而不是研发绝对额。
4. 事件：8-K、Form 4、财报日期距离和事件类型。
5. 动量：复权后的 12-1 月、6-1 月和 20 日动量。
6. 低波：下行波动率、残差波动率。
7. 流动性：20/60 日平均成交额、Amihud、点差代理。
8. 空头异常：short-volume 比例的自身历史 z-score。
9. 期权异常：IV term structure、skew、P/C 异常和次日 OI 确认。
10. 宏观 regime：收益率曲线、利率波动与大盘广度。

横截面合成应使用 winsorized percentile rank 或 robust z-score，做行业和市值中性化，并保证所有财务数据仅从公开时间后的下一个可交易时点生效。

## 14. 最终判断

| 评估项 | 结论 |
|---|---|
| 作为数据接口学习材料 | 高价值 |
| 作为个人研究原型 | 中高价值 |
| 作为生产数据 SDK | 低，需要重构和测试 |
| 作为现成美股选股策略 | 不具备 |
| 作为历史回测数据源 | 不合格，缺 PIT、复权和退市样本 |
| SEC/宏观能力借鉴价值 | 高 |
| 期权/short-volume 直接信号可信度 | 低 |
| 商业使用可行性 | 仅部分官方源可考虑，仍需合规复核 |

最优借鉴顺序：

1. 先引入 SEC 申报事件和 XBRL 数据适配思想。
