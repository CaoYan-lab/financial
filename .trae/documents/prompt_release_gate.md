# 新版提示词发布门禁

本轮完成本地新版提示词实盘接入和长桥自动提交门禁切换。不部署云端，本地测试过程不提交、不撤销真实订单。

## 数据语义修复

- 富途证券融资使用 `exposure_level` 和 `risk_status`；期货专用 `risk_level` 不混用。
- `margin_call_margin` 为保证金阈值，不当作待缴金额；权益与保证金比较使用同计价币种。
- 富途 `power` 与 `max_power_short` 不能混为一谈；零资金不能通过逻辑or被替换。
- 账户和持仓读取失败必须使快照不可用，不能等价为空仓。
- 可平量使用富途 `can_sell_qty`、长桥 `availableQuantity`。缺失、负数、不有限或超总持仓时未知，不推断等于总持仓。

依据：https://openapi.futunn.com/futu-api-doc/trade/get-funds.html 、 https://openapi.futunn.com/futu-api-doc/trade/trade.html 、长桥已安装SDK类型定义。

## 模式控制

界面提供旧版、影子和新版实盘状态。默认账户和租户绑定均可保存三种模式；租户单票、组合和挂单使用同一绑定作用域读取模式。不得将前端选项状态作为权限校验，也不得通过传入`verified`等字段伪造验收。

模式配置使用服务端生成的券商/租户绑定键，Web与Worker使用同一PostgreSQL存储。非云本地使用SQLite事务，不靠单进程内存。环境角色覆盖优先、界面显示覆盖来源；非法环境模式失败关闭。

切换使用版本号乐观锁，避免旧页面覆盖新状态。切换只影响提示词，不修改自动提交或自动撤单开关。影子替代对应决策，不是旧版并行继续执行。权限继承现有云认证、多租户绑定和富途二次解锁，新增本地路由只接受本机访问；写入要求同源且显式确认。

## 验收底线

必须分别验证单票、组合、挂单真实输入，存在开仓/必要减仓/风险挂单而非全HOLD。当前合成样本、mock测试不能作为真实样本。每个样本要关联版本、账户、模型、策略和环境；缺失/过期/未知保持失败。

新版实盘输出必须同时通过严格结构契约、政策校验和响应时效校验。后端按策略权益比例计算组合及单笔损失预算，扣除可识别的待确认订单风险；无法确认预留时耗尽可用预算。提交前再次刷新账户并核验行情，价格偏离超过2%或快照过期即拒绝。提交使用跨进程文件锁串行化。停止价只是失效条件，不等于保证成交或已存在止损单。

## 2026-09-13 实施状态

结论：默认账户的新版实盘执行链已在本地开放，长桥本地配置已切换为新版实盘并开启自动提交。2026-09-14 已在本地接入租户新版挂单监管；云端配置和云端部署仍未变更。

已实现：

- 账户、持仓查询异常失败关闭；富途只读账户查询30秒超时并终止子进程。
- 富途融资字段语义及有限数校验，保留合法零；删除卖空购买力回退和用现金比例推算汇率的逻辑。
- 两券商可平量传递；长桥风险等级拒绝空白、布尔、非整数及越界。
- 最终提交检查账户、币种、时效、持仓方向、可平量和融资准入；富途强制刷新并重跑现有策略风控。
- 富途卖空最大可卖数量尚未接入，因此最终提交拒绝新增空头；这同样影响旧版，不是仅提示词约束。
- 单账户两券商进程内确认互斥；校验期间用户拒绝订单后不再提交。这不等于多实例原子提交。
- 影子审计结果即使误入待确认队列也不能通过两券商及长桥租户最终提交；新版实盘结果还必须携带有效的契约、政策及时效审计凭证。
- `/api/live-trading/prompt-mode` 与 `/api/longbridge/live-trading/prompt-mode` 提供 GET/PUT；只接受 `mode`、`expectedRevision`、`confirmed`。默认账户和租户绑定均允许保存live，额外验收字段返回400。
- 云端 PostgreSQL、本地 SQLite 事务保存模式、版本及最近50次切换；租户绑定由服务端确定，三个决策入口读取同一存储。数据库异常不回退到旧版。
- 环境覆盖逐角色显示且覆盖期间拒绝界面改值。反向代理若改写 Host/协议，需配置 `TRADING_PROMPT_PUBLIC_ORIGIN` 为浏览器实际同源地址。
- 两券商页面提供旧版、影子、新版实盘选择、确认和刷新。提示词切换本身不联动自动提交或自动撤单；本地长桥通过环境配置分别开启提示词实盘与自动提交。
- 单票、组合、挂单三条路径均消费同一新版严格输出；影子模式仍只记录审计。模型输出失败、数据缺失或超时不会回退旧版。
- 租户挂单使用 `userId:bindingId` 作用域和该绑定独立的账户、持仓、订单及行情上下文。新版影子不撤单；新版实盘仅在原订单开平仓效果明确、订单归属和可撤状态有效、模型高置信度建议撤单且自动撤单已开启时，经过数据库原子认领和券商状态复核后撤单。
- 本地提交使用账户级跨进程锁；模型结果生成后，提交端重新检查账户、持仓、可平数量、市场时段、行情时效和2%价格偏离。

仍保持的限制：

1. 历史租户订单若缺少原始 `positionEffect`，新版挂单监管保持 `KEEP`，不根据买卖方向猜测开平仓用途。
2. 港股费用、融资借券成本或订单风险字段无法可靠计算时保持关闭失败，不以0代替。
3. 模型返回的失效价和退出条件是后续决策契约，不自动创建券商止损单。
4. 本地切换不代表云端发布；云端环境变量和持久化配置必须在二次确认后单独变更。

本轮没有提交、推送或部署，没有真实下单/撤单，也没有修改线上模式。本地 `.env.local` 已设置 `LONGBRIDGE_LIVE_TRADING_ENABLED=true`、`LONGBRIDGE_AUTO_SUBMIT_ENABLED=true`；提示词模式通过本地SQLite保存为live，不使用环境变量强制覆盖，因此界面仍可切回旧版或影子模式。
